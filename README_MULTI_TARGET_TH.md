# RRT Game Lab — Multi-Target Tracking Experiment 07

[ทดลองออนไลน์](https://nustanakritwithai.github.io/RRT-Game-Lab/multi-target.html) · [สนามดวลหลัก](https://nustanakritwithai.github.io/RRT-Game-Lab/)

## ทดลองอะไร

สนามทดลองแยกจาก RRT Arena V0.6.3 ใช้ **ผู้ติดตาม 1 ตัว** และ **บอตเป้าหมาย 4–24 ตัว** ที่มีพฤติกรรมแบบกฎง่าย ๆ เพื่อศึกษาการตรวจจับหลายเป้าหมายในเวลาเดียวกัน (multi-target detection/tracking) และการเลือกเป้าหมายไล่จับทีละตัว (single-target pursuit + retargeting)

คำสั่งบอต: `stay` หยุดนิ่ง, `patrol` เดินลาดตระเวน, `wander` เดินสุ่ม, `flee` หนีเมื่อผู้ติดตามใกล้และเห็นได้, `approach` เดินเข้าหาผู้ติดตาม

## สถาปัตยกรรม

1. **World:** ตำแหน่งจริงของบอตใช้เฉพาะการจำลอง การตรวจการชนและเซนเซอร์
2. **Perception:** เซนเซอร์คำนวณจากระยะ มุมรับรู้ (FOV) และสิ่งกีดขวางที่บังแนวสายตา
3. **Multi-target tracks:** เก็บสถานะ `visible` หรือ `memory` พร้อมความเชื่อมั่นที่ลดตามเวลา; บอตที่ไม่เคยเห็นไม่ถูกเพิ่มในข้อมูลเลือกเป้าหมาย
4. **Selector:** กำหนดเป้าหมายหลักจากนโยบายเห็นชัด/ใกล้/บอตหนี/ความจำ และมีโบนัสยึดเป้าหมายเดิมกันสลับถี่
5. **RRT Planner:** ใช้ RRT กับ goal bias และ corridor sampling; ตรวจการชนตลอดเส้นทางและวางแผนใหม่เมื่อเป้าหมายเคลื่อน
6. **Movement:** ผู้ติดตามเคลื่อนที่ตามเส้น RRT; เมื่ออยู่ในระยะสัมผัสจริงและมองเห็นได้จึงนับว่าแตะจับสำเร็จ แล้วให้บอตกลับมาทดลองใหม่ใน 4 วินาที

โหมด “แสดงเป้าหมายจริง” เป็นเพียงภาพสำหรับคนทดลอง ระบบตัดสินใจของผู้ติดตามไม่อ่านตำแหน่งเป้าหมายที่ไม่อยู่ใน tracks

## วิธีใช้งาน

1. เปิดหน้า `multi-target.html` กด **เริ่มจำลอง**
2. สังเกตจำนวนบอตที่มองเห็น (`visible`), ที่ยังจำได้ (`memory`), และเป้าหมายที่กำลังไล่
3. เปลี่ยนคำสั่งบอตรายตัว หรือใช้ปุ่มส่งคำสั่งให้ทุกตัว; ลองให้บอตบางตัวอยู่กับที่ บางตัวเดินสุ่ม บางตัวหนี
4. เปลี่ยน **ลำดับความสำคัญเป้าหมาย** และ **รัศมีเซนเซอร์** เพื่อดูการสลับเป้าหมาย
5. ทดลองโกดัง ทางเดินแคบ หรือสนามโล่ง; เปลี่ยน FOV และ Goal Bias เปรียบเทียบการวางแผน RRT
6. เพิ่มหรือลดจำนวนบอตและทดสอบ 24 ตัว; ค่าจำนวนบอตบน slider จะใช้เมื่อรีเซ็ต

## ข้อจำกัด

- เป็นการจำลองติดตาม/แตะจับ ไม่ใช่ระบบยิงอาวุธอัตโนมัติ
- เป้าหมายใช้ local steering พื้นฐาน อาจติดมุมบางรูปแบบได้; ผู้ติดตามใช้ RRT ที่ซับซ้อนกว่า
- ความเชื่อมั่นการจำเป็น heuristic ที่ลดตามเวลาจากการมองเห็น ไม่ใช่ Bayesian multi-object tracking เต็มรูปแบบ และยังไม่มี data association เมื่อบอตเปลี่ยน ID
- ผู้ติดตามไล่ได้ **หนึ่งตัวในหนึ่งช่วง** แต่จำเป้าหมายหลายตัวพร้อมกัน จึงยังไม่ได้ควบคุมฝูงโดรนหลายตัวหรือโจมตีหลายเป้าหมายพร้อมกัน
- การทดสอบ Node/browser ยืนยันพฤติกรรมในชุดกรณีที่ออกแบบ ไม่รับประกันความเหมาะสมของเส้นทางในทุกแผนที่

## ต่อยอด

เพิ่มกลุ่มผู้ติดตามหลายตัว, target assignment, threat map, route sharing, occlusion-aware prediction, ID reassociation, replay/metrics, และแยกใช้โมเดล AI ผ่าน tool calling ในภายหลัง
