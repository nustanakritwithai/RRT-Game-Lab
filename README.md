# RRT Arena v0.6.1 — Memory-Guided RRT

[เล่นบน GitHub Pages](https://nustanakritwithai.github.io/RRT-Game-Lab/) · [ไฟล์เกม](./index.html)

เกมทดลองการวางแผนเส้นทางของบอต 2 ตัวบนมือถือ โดยใช้ Tactical Rules + RRT + ความจำของแต่ละบอต (ยัง **ไม่** ใช้ LLM หรือ API Key)

## ทำไมกิ่ง RRT ถึงวิ่งไปข้างหลัง?

ใน RRT ปกติการสุ่มส่วนใหญ่กระจายทั่วสนาม แม้ระบบจะทราบตำแหน่งที่เคยพบศัตรู จึงเกิดกิ่งที่ดูไม่เกี่ยวกับเป้าหมาย วิธีแก้ใน v0.6.1 คือ **Memory-Guided Sampling**: กำหนดพื้นที่สุ่มที่มีน้ำหนักมากขึ้นสำหรับเส้นทางจากตัวเองสู่เป้าหมายและบริเวณที่พบศัตรูจริงจากการรับรู้ในอดีต ทั้งนี้ยังต้องสงวนการสำรวจทั่วสนาม เพราะบางสถานการณ์การเริ่มเดินถอยหลังเป็นทางอ้อมที่ถูกต้อง

## ฟีเจอร์

- **Guidance 0–100%**: 0% = เหลือ Goal Bias + สุ่มทั่วสนามตาม RRT ปกติ; ค่าสูงขึ้น = โฟกัสแนวทางไปจุดหมาย + พื้นที่ที่ศัตรูเคยถูกพบ
- **Last-Seen Region**: ใช้ตำแหน่งศัตรูล่าสุดเฉพาะเมื่อบอตเคยเห็นจริง วงค้นหาขยายตามอายุข้อมูล ไม่ใช่การมองเห็นผ่านกำแพง
- **Past Encounters**: สะสมตำแหน่งที่บอตสังเกตเห็นศัตรูจริง ใช้เป็นจุดสนใจการสำรวจ (ไม่ใช่ตำแหน่งปัจจุบันที่รู้แน่นอน)
- **Cross-round Memory**: หากเปิดตัวเลือกจดจำข้ามรอบและใช้แผนที่เดิม ความทรงจำสถานที่เคยพบศัตรูและจุดอันตรายถูกเก็บข้ามรอบโดยลดความเข้มข้นลง แต่ไม่เก็บ `lastSeen` เป็นตำแหน่งสด
- **Global fallback**: คงอย่างน้อย 12% ของการสุ่มหลัง Goal Bias ไว้ทั่วสนาม และเพิ่มการสำรวจอิสระเมื่อหาเส้นทางล้มเหลวซ้ำ
- **Learning UI**: แสดงสัดส่วนการสุ่มจากจุดเป้าหมาย ความจำ แนวทาง และทั่วสนาม แนะนำให้เปรียบเทียบค่าสองขั้วโดยกดรีเซ็ต
- **Safety**: ยังคงตรวจสอบการชนตลอดกิ่ง การเคลื่อนที่ และกระสุน พร้อมระบบใช้กฎอัตโนมัติและ Replay

**ความหมายสำคัญ**: Guidance 85% ไม่ได้แปลว่า 85% ของกิ่งอยู่ตรงจุดศัตรูเสมอไป มี Goal Bias การสำรวจทั่วไป และเป้าหมายเช่นถอย/ที่กำบังที่ต้องคำนึงถึงอีกด้วย ระบบเป็น heuristic ไม่รับประกันเส้นทางสั้นที่สุด

## ทดสอบด้วย Node.js

```bash
node --test rrt_arena_v05_core.test.cjs rrt_arena_memory_v061.test.cjs rrt_arena_guided_v061.test.cjs
```

การทดสอบเพิ่ม: `index.html` ทำงานบน Playwright viewport มือถือและเดสก์ท็อป; ตรวจความปลอดภัยหลังเพิ่มกำแพง, ข้อมูลการมองเห็น, Replay, memory carry และ UI guidance

## สถาปัตยกรรม

Perception → Observation Memory → Tactical Goal → Memory-Guided Sampler → Risk-Aware RRT (cost-aware local parent selection) → Movement & Combat → Replay

โปรแกรมใน `index.html` ฝัง JavaScript ครบทุกโมดูลเพื่อเล่นออฟไลน์ได้ ส่วน `.js`/`.test.cjs` แยกไว้เพื่อทำ unit tests และพัฒนาต่อบน GitHub

**ข้อจำกัด**: ไม่มีโมเดลภาษา, ไม่ได้ใช้ RRT*, ความทรงจำไม่ได้เป็นแบบจำลองโอกาสจริง และไม่มีข้อมูลคู่ต่อสู้ล่วงหน้าที่บอตไม่เคยรับรู้
